# Privacy and security boundaries

Selected image bytes, filenames, EXIF/GPS, clipboard data and output are never sent to a conversion service, backend or analytics endpoint. There is no payload history, remote URL import, user-code execution, unsafe user-generated HTML, or sensitive console logging. React renders metadata and filenames as text. Preview/download Blob URLs are local and revoked. Fonts, scripts and sample artwork are self-hosted. The sample button fetches a bundled image; it does not transmit selected files.

The default build has no analytics or advertising provider. Ordinary page/asset requests still reach hosting, which may process connection logs. The site stores only a theme preference. Browser extensions, compromised devices, screenshots, clipboard history and downloaded output are outside this processing boundary. Local processing is not a promise of perfect security.

Binary signatures and header dimensions are checked before decoding. Actual decode success is required. Unsupported/animated inputs are rejected explicitly. Source/output dimensions, bytes, batches and compression iterations are bounded; workers are cancellable and time-limited. See architecture.md for exact limits and cooperative fallback behavior. A generation counter prevents stale output from replacing newly selected data.

The build creates `dist/_headers` from the final HTML's inline script hashes. JavaScript script unsafe-inline and unsafe-eval are absent. The narrower wasm-unsafe-eval permission allows compilation of the bundled WebP encoder; it does not enable JavaScript eval. The encoder’s JavaScript uses neither eval nor new Function. Same-origin scripts, workers, fonts and connections are permitted; external connections are denied by default. `img-src` permits local Blob/data previews. Inline style permission supports React visual crop styles. Security headers also deny framing and MIME sniffing, restrict device capabilities, and configure referrer behavior and HSTS without assuming control of all subdomains.

@jsquash/webp (Apache-2.0, with libwebp notices shipped under public/licenses) is an on-demand local WebP encoding fallback; exifr (MIT) reads metadata; fflate (MIT) writes ZIPs. Both are split out of the initial homepage processing bundle. Inter uses SIL OFL, shipped in `public/licenses`. Sharp (Apache-2.0) is development-only for deterministic fixtures and independent output decoding; it is not deployed as server-side processing. Commit `pnpm-lock.yaml`, install frozen, and audit dependencies before release. An audit is a snapshot, not a guarantee.

Before adding analytics or ads, identify actual providers, update disclosures/consent and narrow CSP origins. Do not include image data, filenames, metadata, clipboard values or output in events. Do not relax script policy with wildcards or unsafe-eval to work around an integration failure.
