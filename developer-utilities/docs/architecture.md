# Architecture and transformation contracts

Astro statically generates 20 HTML routes plus SEO endpoints. Only tool workspaces hydrate with React. A small native script handles search, navigation, and theme on other pages. The tool registry contains slugs, categories, icons, searchable keywords, related IDs, and metadata; each ID maps to unique educational content. React lazy imports separate data, encoding, UUID, regex, time, and reference interfaces. CodeMirror is used by editor workspaces with line numbers and JSON syntax highlighting; each editor has a plain textarea alternative. Inter and JetBrains Mono are self-hosted.

## Processing

JSON, CSV, JWT, Base64, regex, timestamps, URL transformations, and cron run in disposable module Web Workers. Each action gets a fresh worker. A new run, clear, edit, timeout, or unmount terminates the previous worker. General operations have a five-second budget; regex has 1.5 seconds, including replacement processing. UUID generation uses the main browser's `crypto.randomUUID()`. HTTP lookup uses a bundled structured dataset with no network dependency after assets load.

All individual text inputs and local files have a 1,000,000-byte limit, measured as UTF-8 for editor text. JSON nesting is limited to 150 levels. JSON differences are bounded at 10,000. Regex patterns are at most 2,000 characters, with fewer than 5,000 matches. UUID counts are integers from 1 through 1,000. Preview tables show the first 20 data records; exports contain the full result.

## Exact semantics

- JSON uses standard `JSON.parse` / `JSON.stringify`. A lexical walk detects duplicate keys, including escaped aliases, and warns that the last value survives. JSON numbers follow JavaScript precision. Comments and trailing commas are invalid.
- Structural diff distinguishes scalar types, null, arrays, and objects. Paths use bracket notation with JSON-escaped keys. Object property order is ignored by default; optional order comparison reports a separate order change. Array-order-insensitive mode compares recursive multisets and consumes each duplicate occurrence individually. Unmatched elements become additions/removals, not speculative changed pairs.
- Papa Parse handles CSV records and quoting. JSON export flattens nonempty nested objects with a configurable separator, rejects colliding paths, unions record keys, and emits CRLF. Arrays and empty objects are JSON strings; null and missing are empty cells. Formula protection is enabled by default and explicitly warns about apostrophe prefixes.
- CSV import rejects duplicate/empty headers, inconsistent widths, and malformed quoting. It supports headerless arrays, configurable whitespace trimming, delimiter, and indentation. No type inference occurs; all cells remain strings.
- JWT inspection accepts three compact segments and JSON objects in header/payload. Empty signatures can be inspected. Header and payload are Base64URL-decoded; no key or verification primitive is used. NumericDate claims are interpreted as seconds against the device clock. Output explicitly includes `signatureVerified: false`.
- Base64 starts with UTF-8 bytes, validates alphabets and padding, and rejects noncanonical padding bits or invalid UTF-8 output. URL-safe encoding omits padding. Binary downloads are not offered as decoded text.
- UUID generation uses secure browser APIs with no Math.random fallback. Validation checks UUID v4 version and variant shape; it cannot prove a supplied ID's randomness or uniqueness.
- Regex is JavaScript RegExp, not PCRE. Flags are explicit and validated. Empty matches advance safely, including surrogate pairs in Unicode mode. Match offsets are UTF-16 code units. Replacement uses JavaScript replacement tokens. The worker timeout is a practical bound, not a formal guarantee of safety or pattern quality.
- Timestamp units are explicit. ISO input requires an explicit Z or offset. Invalid calendar dates are rejected. Selected-zone output uses Intl and local output uses the browser's zone. Unix timestamps do not model leap seconds.
- Cron supports numeric five-field syntax (*, lists, ranges, steps). DOM/DOW restricted simultaneously use OR. Sunday 0 and 7 are accepted. Extensions and named fields are rejected. cron-parser determines timezone/DST and next-run behavior. The description is generated by cronstrue. Verify against the intended production scheduler.
- URL operations distinguish component, URI, and form rules. Form query spaces become + and literal plus signs become %2B. Inspection retains duplicate parameter rows, rejects malformed query escapes, and never fetches the target. Encoding is explicit and will encode a literal percent sign; the UI explains avoiding unintentional double encoding.
- HTTP status data is a selected set of registered, commonly used codes checked against IANA. Unassigned, vendor-only, deprecated/reserved-unused codes are omitted; 402 is explicitly described as reserved for future use. Each entry includes an example, guidance, and documentation link.

## Adding a tool

Add an ID and metadata to `src/data/tools.ts`, a content entry in `src/content/tools/index.ts`, a pure engine and tests, an appropriate lazy workspace, a worker dispatch case when needed, and real E2E coverage. The dynamic Astro route generates the tool page, breadcrumbs, metadata, JSON-LD, guide, FAQs, and related tools from the registry. Confirm sitemap and CSP length limits when scaling.
